## 修复：saver 命令相对导入越界崩溃（用户报障）
- 现象：`nova-forge saver` 启动即抛 `ImportError: attempted relative import beyond top-level package`，
  traceback 指向 `cmd_saver.py:23 from ....resources import resources_rc`。
- 根因：`resources_rc.py` 实际在项目根 `resources/`（与 `src` 同级，目录无 `__init__.py`，
  PEP 420 命名空间包），**不在** `nova_forge` 包内。相对导入无法跳出顶层包；
  4 个点（从 `nova_forge.command` 起算）更是必然越界。2 个点同样错误（会找不存在的 `nova_forge.resources`）。
- 修复：与同类命令 `cmd_icons.py` 对齐，改为
  `try: from resources import resources_rc / except ImportError: 降级 WARN`。
  - 实测：editable 环境项目根在 sys.path，绝对导入成功（resources_rc 已加载）。
  - PyPI 安装时 `packages.find` 只收 `nova_forge*`，`resources/` 不随包分发 → try/except 保证 GUI 仍能启动。
  - `cmd_saver.py` 首行日期按 D-008 更新为 `星期二 2026-11-24 12:25`。
- 验证：`import nova_forge.command.cmd_saver` 成功、resources_rc 已加载、run_clip_saver 可调用；全量 19 项单测通过。
- **账实隐患（未改，需用户决策）**：`resources_rc.py` 是 rcc 生成物且放在包外，PyPI 用户运行 saver/icons 时
  窗口图标必然缺失（只能降级）。若要修，应把编译产物纳入 `nova_forge` 包并调整 qrc 生成脚本输出路径——
  涉及打包策略，超出本次修障范围，未擅动。

## 修复：saver 自动监听失效（用户报障）
- 现象：`nova-forge saver` 启动后剪贴板复制内容，日志显示"触发剪贴板监听"、信号也发出，但文件不写入。
- 根因：`cmd_saver.run_clip_saver()` 中 `SaverController(window)` 是裸调用，无引用持有 → 立即被 GC 回收
  → `signal_parse_requested.connect(self.scan_and_save)` 的绑定方法随对象销毁失效。
  对照实验实证：持有引用时 `scan_and_save` 被调用；不持有时信号发出但槽无响应。
- 修复：`window._saver_controller = SaverController(window)`，控制器生命周期与窗口绑定。
  `cmd_saver.py` / `test_smoke.py` 首行日期更新为 12:35。
- 回归测试：`SaverLifecycleTests.test_controller_is_kept_alive_by_window`，mock 掉 QApplication/SaverWindow，
  断言控制器被挂到 window 属性上。全量 20 项通过；端到端诊断确认信号+文本加载闭环恢复。
- CHANGELOG Unreleased 补两条 saver 修复 + 测试条目。
- **教训（通用）**：PySide6 中 `signal.connect(obj.method)` 不会保活 obj 本身；控制器/槽宿主必须显式持有引用
  （挂窗口属性或局部变量），否则 GC 后"信号发了但槽不执行"，极具迷惑性。
